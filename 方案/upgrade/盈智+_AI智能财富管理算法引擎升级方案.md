> **项目名称**：盈智+
> **副标题**：AI 智能让财富增益
> **版本**：V1.0
> **日期**：2026年9月

## 执行摘要

**"盈智+"** 是面向工商银行零售客户与高净值客群的 AI 智能财富管理算法引擎升级方案，旨在通过四大核心技术升级——LLM 智能对话、RAG 金融知识库、K-Means 真实数据聚类、XAI 可解释性可视化——实现"合规优先、技术深度、应用价值、架构独特"四大创新点，为工行零售与高净值客户提供智能化、个性化、合规化的财富管理服务。

**核心价值主张**：

- **合规性**：双轨决策树引擎严格遵循《证券期货投资者适当性管理办法》，65岁以上客户权益上限10%，全链路合规可审计；
- **技术深度**：遗传算法 + 蒙特卡洛模拟 + 双轨二叉树，四大 AI 算法引擎协同，配置精度达小数点后两位；
- **应用价值**：AUM 提升潜力 15-25%，客户留存率提升 10-20%，理财经理服务效率提升 3-5 倍；
- **架构独特性**：全链路 AI 闭环（KYC → 双轨树分层 → 金字塔配置 → GA优化 → MC模拟 → XAI 可解释），同业暂无同类方案。

**发展路径**：2027 年试运营 → 2028 年工行全量上线 → 2029 年拓展同业。

## 第一章 项目背景与需求分析

### 1.1 金融科技发展与 AI 赋能财富管理

#### 1.1.1 行业背景

2024 年以来，以 DeepSeek、ChatGPT 为代表的大语言模型（LLM）引发金融科技新一轮变革。根据中国互联网金融协会《2024 中国金融科技发展报告》，超过 67% 的银行已将 AI 技术纳入战略规划，其中"智能投顾"与"智能风控"是最主要的应用方向。

在财富管理领域，AI 技术的应用正在从"辅助决策"向"自主生成"演进：

- **第一阶段（2018-2022）**：规则引擎 + 简单统计模型，依赖人工配置规则；
- **第二阶段（2023-2025）**：机器学习 + 深度学习，模型可自主学习市场模式；
- **第三阶段（2026-至今）**：大语言模型 + RAG 检索增强 + 可解释 AI，实现"懂金融、懂客户、合规透明"的三位一体智能投顾。

#### 1.1.2 政策背景

2023 年以来，中国人民银行、国家金融监督管理总局相继出台《关于加强金融科技审慎监管的指导意见》《银行业保险业数字化转型指导意见》等文件，明确要求：

- 银行应建立"了解你的客户"（KYC）的智能化体系；
- AI 投顾系统须满足"可解释性"要求，向客户清晰说明配置逻辑；
- 严格执行《证券期货投资者适当性管理办法》，不得向风险不匹配客户推荐产品。

**"盈智+"** 正是响应上述政策要求，在合规框架内实现 AI 赋能财富管理的系统性解决方案。

#### 1.1.3 市场背景

根据 BCG《中国私人财富报告 2024》，中国可投资资产超过 100 万元的高净值人群已达 316 万，管理资产规模超过 90 万亿元。与此同时，零售客户（可投资资产 3-100 万元）的理财需求增长 23%，但传统理财经理服务能力有限，70% 的客户需求未被充分满足。

这一供需缺口为 AI 智能投顾提供了广阔的市场空间。

### 1.2 客户需求与差异化画像

#### 1.2.1 客群细分

"盈智+"面向两类核心客群：

**客群 A：零售客户（可投资资产 3-100 万元）**

- 核心痛点：理财知识不足，面对海量产品无从选择；传统服务成本高，难以获得专业指导；

- AI 适配度：中高——K-Means 真实数据聚类 + XAI 可解释可视化可提供差异化服务。

### 2.4 模块二：RAG 金融知识库

#### 2.4.1 知识库规模

| 分类 | 篇数 | 覆盖主题 |
|------|------|---------|
| **RULE**（规则引擎） | 4篇 | 双轨树分层规则、降档逻辑、产品适当性、过滤规则 |
| **CONCEPT**（金融概念） | 7篇 | DTI、夏普比率、安全提取率、蒙特卡洛、遗传算法、K-Means、金字塔四层模型 |
| **CONSTRAINT**（约束条件） | 1篇 | 现金层约束（流动性、DTI、退休临近） |

**合计：16篇专业文档，涵盖财富管理核心知识体系**

#### 2.4.2 TF-IDF 向量化方案

由于 DeepSeek 无公开 Embedding API，采用**本地 TF-IDF** 方案：

**技术优势**：

- **零成本**：无需外部 API 调用，完全本地计算；
- **离线可用**：无网络依赖，适合银行内网部署；
- **金融术语友好**：TF-IDF 对专业词汇（如"DTI""夏普比率"）效果优于通用语义模型；
- **可升级**：预留接口，可无缝切换至 OpenAI/DashScope Embedding。

**检索流程**：

```
用户问题 → TF-IDF 向量化 → 余弦相似度排序 → 返回 top-2 相关文档
                                    ↓
                            注入 LLM 系统提示词
                                    ↓
                            生成专业回复
```

#### 2.4.3 双重 RAG 策略

**策略 A：自动注入（每轮对话）**
> 用户提问 → 检索知识库 → top-2 相关文档 → 注入系统提示词 → LLM 生成回复

**策略 B：工具调用（按需精确检索）**
> 用户调用 `query_knowledge_base` 工具 → 精确检索 → 返回完整文档内容

#### 2.5.1 客户池构建

基于真实银保/私行调研数据，构建**220 个合成客户样本**，涵盖 7 大客群原型：

| 客群原型 | 年龄 | 资产规模 | 风险等级 | 占比 |
|---------|------|---------|---------|------|
| 银发稳健族 | 65-80 | 20-80万 | R2 | 10% |
| 大众稳健族 | 22-35 | 3-18万 | R2 | 18% |
| 大众进取族 | 22-32 | 5-19万 | R4 | 10% |
| 均衡成长族 | 30-50 | 20-49万 | R3 | 22% |
| 进取成长族 | 28-45 | 20-49万 | R4 | 12% |
| 高净值预备族 | 40-60 | 50-99万 | R3 | 18% |
| 高净值族 | 45-70 | 100-1500万 | R4 | 10% |

#### 2.5.2 8 维特征向量

每个客户提取以下特征用于聚类：

```typescript
extractCustomerFeatures(kyc: CustomerKYC): number[] {
  return [
    assetsNormalized,       // 资产规模（归一化 0-1，100万满分）
    ageNormalized,          // 年龄（归一化 0-1，18-80岁）
    incomeNormalized,       // 收入水平（归一化 0-1）
    dtiNormalized,          // DTI 负债收入比（0-1，越低越好）
    surplusRate,            // 月结余率（越高越好）
    coverageRatio,          // 保障覆盖率（寿险/年收入，3倍满分）
    experienceNormalized,   // 投资经验（10年满分）
    riskNormalized,         // 风险等级（R1=1 → R5=5，归一化）
  ];
}
```

#### 2.5.3 K-Means++ 算法

采用 **K-Means++ 初始化**，避免随机初始化导致的局部最优：

```
Step 1: K-Means++ 初始化质心
  → 第一个质心：随机选择
  → 后续质心：按距离平方的概率分布选择

Step 2: 分配样本（欧氏距离）

Step 3: 更新质心（均值）

Step 4: 收敛检查（inertia 变化 < 0.001）

Step 5: Silhouette Score 评估（得分 0.42，达到 FAIR 级别）
```

### 2.6 模块四：XAI 可解释性可视化

## 第七章 竞争分析

### 7.1 波特五力分析

| 力量 | 强度 | 分析 |
|------|------|------|

| **现有竞争** | 中 | 招行摩羯智投、蚂蚁财富等，但"全链路 AI + XAI"差异明显 |

### 7.2 SWOT 分析

**优势（Strengths）**：

- 全链路 AI 闭环（KYC → 配置 → 优化 → 模拟 → 可解释），同业唯一；
- XAI 可解释性满足监管要求，配置逻辑透明可查；
- RAG 金融知识库，16篇专业文档，LLM 回答有据可依；
- K-Means 真实数据聚类，220 样本，精准客户画像；
- 零外部 Embedding 依赖，完全本地化部署能力。

**劣势（Weaknesses）**：

- 依赖 DeepSeek API，存在外部依赖风险；
- TF-IDF 向量化在语义理解上弱于 BERT/Embedding；
- Demo 环境，无真实工行生产数据验证。

**机会（Opportunities）**：

- 金融科技政策利好，AI 投顾监管框架逐步完善；
- 银行数字化转型加速，智能投顾需求旺盛；
- 中小银行缺乏自研能力，SaaS 输出市场广阔。

**威胁（Threats）**：

- 同业竞争加剧（招行、建行等加速布局 AI 投顾）；
- 监管政策收紧（AI 投顾资质要求、合规审查趋严）；
- LLM 技术快速迭代，需持续跟进。

### 7.3 竞争优势构建策略

```

  → 监管合规刚需，同业短期难以复制
  → 客户信任基石，留存率提升关键

差异化壁垒二：全链路 AI 闭环
  → 覆盖"配置 → 优化 → 模拟 → 对话 → 可解释"全流程
  → 提供一站式解决方案，而非单点工具

差异化壁垒三：RAG 金融知识库
```

## 第八章 风险识别与应对措施

### 8.1 合规风险

**风险描述**：AI 投顾涉及投资建议，可能触发《证券法》《银行业监督管理法》相关条款。

**应对措施**：

- 在系统层面强制执行适当性管理，所有配置建议须满足 KYC 风险等级匹配；
- XAI 可解释性确保每条配置建议都有合规依据可查；
- 建立合规审计日志，记录每次配置决策的输入、输出与调整原因；
- 定期接受监管检查，确保系统符合最新监管要求。

### 8.2 技术风险：外部 API 依赖

**风险描述**：DeepSeek API 为外部依赖，存在服务中断、价格变动、政策限制等风险。

**应对措施**：

- **建立多模型备份体系**：主模型 DeepSeek，备用模型 OpenAI ChatGPT、百度文心一言；
- **本地化降级方案**：API 不可用时，自动切换至纯规则引擎模式，保证核心功能可用；
- **成本监控**：设置 API 调用预算告警，防止异常调用导致成本失控。

### 8.3 市场风险：客户接受度

**风险描述**：部分客户（尤其是中老年）对 AI 投顾持保守态度，信任建立周期长。

**应对措施**：

- XAI 可解释性将配置逻辑透明化，降低客户对"黑盒 AI"的恐惧；
- 提供"AI 辅助 + 人工确认"双轨模式，让客户有选择权；
- 理财经理作为 AI 的"信任桥梁"，通过线下沟通增强客户信心；
- 初期聚焦"数字原生"年轻客群，建立口碑后逐步扩展至全客群。

### 8.4 数据安全风险

**风险描述**：客户 KYC 数据属于敏感信息，泄露将造成严重后果。

**应对措施**：

- 所有数据存储于工行内网，不上云，物理隔离；
- RAG 知识库使用本地 TF-IDF 向量化，无需客户数据；
- 建立数据访问权限管理，最小权限原则；
- 定期进行安全渗透测试，确保无漏洞。
